## 统一执行摘要

### 当前 Prototype 0 已经收敛的内容

- Prototype 0 只验证：**元素牌 + 真实化学配方 +「叠」是否能形成有意义、值得重复尝试的战斗策略**。
- 测试角色为 **氧 O**；定位为**玩家首个、低门槛、偏直伤、快速进入合成，并保留少量防御／功能分支**的入门型合成输出角色。
- 初始牌组结构为 **10 张真实实例：自身元素 4 + H/C/N 各 1 + 招牌 3**；具体数值仍作为首轮基线参数管理。
- 首批配方候选继续采用 **H₂O、H₂O₂、CO₂、NO**；外部科学证据初核未发现必须替换的理由，但仍需项目正式科学／内容审核签署。
- 标准实验继续使用 **35「叠」且无额外回复**；不为了证明机制有效而擅自降低标准资源量。
- 敌人结构固定为：**固定行动循环 + 展示下一行动意图**；具体 HP／伤害／护盾继续作为配置化测试参数。
- Prototype 0 的最小规则层已经收敛：整数基础伤害、独立 `DamageEvent`、数值护盾、最小 Buff／Debuff、抽牌、治疗、能量、合成事务、状态持续、敌人循环、胜负与配方发现持久化。
- 数值护盾在 Prototype 0 中**不自然按回合清空**，持续到被消耗完或战斗结束。
- Prototype 0 复合效果测试顺序为：**治疗 → Buff → Debuff → 数值护盾 → 资源变化 → 抽牌 → 伤害**。
- 抗性保留 `ResistanceStage` 接口，但 Prototype 0 首轮可玩样本不配置实际抗性；暴击、穿透、复杂反伤与递归被动不进入本轮可玩样本。
- 开发原则：**结构和规则语义先冻结，平衡数值后测试；不预设玩家逐回合唯一正确打法。**
- Prototype 0 不是“工程验证器”，而是一个**短、小、但已经像游戏的可玩原型**。核心交互必须具备足够的视觉、音效和动效反馈，避免因为表现缺失导致对玩法产生假阴性判断。
- 表现资源优先集中在 **合成 → 产物释放 → 命中／护盾反馈 → 首次发现／胜负收束**。不做量产级美术，不等于不做特效。
- 面向独立开发者采用**少里程碑、强正反馈、纵向切片优先**的推进方式：每一阶段都应得到一个明显更完整、更好玩的可运行版本，避免长时间只搭底层架构。
- 工程上不为尚未批准的未来系统预建复杂“防御性”抽象；只保留当前已知扩展点。**规则一致性、原子事务、存档正确性和可复现性仍属于必须保证的正确性，不属于可省略的过度设计。**

### 当前真正剩余的开工前事项

1. 完成首批 4 条配方的项目正式科学／内容签署，并确认开放状态。
2. 批准氧角色与 10 张牌作为 **Prototype 0 Baseline A** 的首轮实现数据；它是开发基线，不是最终平衡。
3. 批准测试敌人的一套首轮基线数值与可选对照参数。
4. 确认 Prototype 0 的**核心表现基线**：合成、出牌、命中、护盾、首次发现、胜负必须有足够的原型级 VFX／SFX／UI 动效；无需等待正式量产资产。
5. 由独立开发者结合现有代码库、工具链和个人产能复核工作量并直接进入纵向切片开发。

> **大局原则：** 当前不再通过继续细化玩家逐回合打法、单张牌最优数字或正式版复杂战斗数学来拖延原型。Prototype 0 的任务是尽快建立可信、可测、可复现的核心玩法闭环，然后用真实试玩结果决定下一步。

## 01｜游戏定位、核心体验与设计理念

### 01.1 产品定义

**TCA 是一款以化学元素拟人化为题材、以真实化学为世界规则骨架的完整买断制单机 RPG。** 玩家在剧情目标驱动下，于具有斜 45°空间感和 HD-2D 观感的 **2.5D 主世界**中自由移动、调查、观察、与角色互动，并进行适量且与情境紧密相关的化学环境交互；地图中的可见敌人通过接触进入**独立的横版 2D、单角色卡牌战斗场景**。玩家在战斗中使用普通元素牌、角色招牌牌与有限资源「叠」，按经科学及内容审核的真实化学配方生成临时产物卡，并通过出牌、合成与资源取舍克敌制胜。

主世界探索与战斗采用不同表现形式，但共享角色、化学知识、长期进度和存档体系。游戏以 **PvE** 为现阶段主要内容，主体为完整、有限、能够通关的单机冒险，而不是日常运营驱动的服务型游戏。

### 01.2 核心体验锚点

TCA 最需要被玩家记住的体验是：

> **“原来卡牌合成还能这么做！”**

这一体验用来判断游戏最有辨识度的玩法是否真正成立。化学合成的惊喜、理解与应用，以及清晰有力的出牌反馈，是核心玩法体验；令人愿意停留、观察和旅行的视觉表现，是重要体验支柱。

该体验锚点描述的是玩家感受，不等于已经确定第一场战斗的具体配方、新手教学时长、合成演出步骤或量化验收阈值。

### 01.3 整体玩法循环

当前统一的整体循环是：

```text
剧情推动探索
  → 探索带来广义的化学发现、线索与组合启发
  → 化学发现丰富卡牌合成与战斗选择
  → 战斗兑现发现价值并推动剧情继续发展
  → 新剧情、角色与世界变化再次驱动探索
```

四个环节必须互相支持，而不是并列存在的剧情系统、地图系统、化学百科与战斗小游戏：

- **剧情提供前进的理由和阶段目标。** 玩家知道为什么出发、当前要推进什么。
- **探索提供发现与沉浸。** 场景、角色、事件、环境异常与可观察的化学现象使旅途本身具有吸引力。
- **化学发现扩大玩法可能性。** 玩家自然获得反应线索、组合思路及未来可能使用的配方方向。
- **战斗兑现发现价值。** 玩家在规则明确的卡牌战斗中尝试、验证并使用化学合成，战斗结果服务剧情和世界进程。

这里的“化学发现”在整体循环中是广义概念，包含知识、线索与组合启发；**正式配方发现仍只在成功合成并生成产物后登记**，两者不可混用。

### 01.4 玩家体验的优先序

| 梯队 | 核心驱动力 | 玩家应持续获得的体验 |
|---|---|---|
| 第一梯队 | **剧情驱动的探索发现** | 知道为什么前进，在旅途中自主移动、观察场景、发现地点与异常，并在回访时产生新认知 |
| 第一梯队 | **角色陪伴** | 认识元素角色、互动、见证隐性成长与关系变化，并感到角色真实参与旅程 |
| 第二梯队 | **化学发现** | 自然接触化学线索、理解元素、尝试反应、积累可复用的知识与正式发现 |
| 第二梯队 | **战斗与构筑** | 有意义的出牌、配方与资源取舍，以及角色差异化策略 |
| 贯穿上述体验 | **视觉沉浸** | 通过 HD-2D 场景、光影、镜头和角色表现建立旅行氛围与视觉吸引力 |
| 融入上述体验 | **收集与完成度** | 由探索和成长自然产生的积累，不独立成为清单刷取主循环 |

剧情是探索的主要发动机，但探索并不被压缩成“沿任务箭头赶路”。基本原则是：**玩家应当知道自己为什么前进、往哪里推进主线，但不必事先知道沿途会发现什么。**

### 01.5 产品与技术目标

| 维度 | 当前统一方向 |
|---|---|
| 商业模式 | **买断制单机 RPG**；主体内容完整、有限、可通关 |
| 主世界 | 2.5D／斜 45°立体空间感；剧情驱动的自由探索；连续进度 |
| 主世界美术 | **参照《歧路旅人》式 HD-2D 观感**：像素风格角色＋空间层次场景＋光影与镜头塑造；不等于确定具体渲染技术 |
| 战斗 | 独立横版 2D、单角色、卡牌驱动、PvE 优先 |
| 普通 PvE 行动时限 | **不默认启用强制 60 秒操作倒计时**；技术超时和特殊限时玩法另行设计 |
| 动画 | 角色主要以逐帧 2D Sprite 动画表现；D1 未推翻此方向 |
| 首版角色规模 | **14 名可玩元素角色**的产品目标 |
| 化学元素范围 | 周期表第 1～3 周期的 **18 种主族元素** |
| 普通战斗时长 | 设计目标约 **5～10 分钟**；取消倒计时不等于节奏问题已经解决 |
| 平台和引擎 | PC、Godot 4.6.2、GDScript；Steam／Epic 为发布渠道方向 |
| 输入及语言 | 键鼠优先、部分手柄支持；不规划触控；首发简体中文 |
| 性能预算 | 目标 60 FPS／约 16.6 ms 每帧、约 1,000 次 2D draw calls、约 2 GB 内存 |
| 测试框架方向 | gdUnit4 6.2.1；以实际用例、运行日志与可复核证据判断验收 |

### 01.6 一体化设计支柱

1. **真实科学与适度幻想并存。** 配方的物质、反应和计量须有可核验科学依据；角色人格、元素天赋、场景能力和叙事表现允许象征化与适度夸张。“现实存在”不等于“游戏已开放合成”。
2. **化学贯穿完整游戏。** 化学知识既作用于战斗产物，也参与环境互动、探索、角色能力和未来叙事；但探索不以大量复杂化学谜题为主体。
3. **剧情、探索、化学与战斗形成因果闭环。** 剧情给出动机，探索产生线索，化学拓展策略，战斗兑现发现并推动世界继续发展。
4. **合成是资源决策。** 真实元素牌可循环，「叠」可节省牌但有限；生成的产物即时入手、用后离场，玩家权衡当回合爆发和后续续航。
5. **角色身份固定而配置有选择。** 角色拥有各自元素、属性、基础牌表和固有招牌；招牌单质可战前替换，普通元素牌的成长构筑遵守基础牌组约束。
6. **发现与角色关系长期累积。** 战斗成功配方进入跨角色图鉴；探索知识、角色解锁、构筑可能和关系变化使玩家重新理解已去过的世界。
7. **沉浸优先于机关密度。** 旅行、观看场景、人物互动和发现惊喜是探索主体；化学交互有存在感，但不以高频、强制、复杂机关持续打断节奏。
8. **世界以内容密度而非面积取胜。** 主世界提供旅行感与自由度，关键地区、城镇、设施、特殊场景集中承载高价值内容。
9. **代表性核心合成体验必须进入主线。** TCA 最有辨识度的化学卡牌合成不能只存在于可错过支线或隐藏内容。

### 01.7 不采用的旧产品与机制

现行设计不采用四人组队共享牌组、不用缺牌直接判负、不设置独立溶剂系统，不把化合物二次合成列入当前战斗机制；不沿用“所有角色十张牌”“仅两张招牌”“起手全随机”“行动 30 秒”等旧口径。**普通 PvE 也不再采用固定 60 秒强制操作倒计时及其硬截止派生规则。**

游戏不以每日／每周任务、体力、赛季、运营型角色池、无限刷取、为更新周期设置的资源墙和无节制数值膨胀构造主体；也不把探索设计成持续高频的复杂机关解谜集合。

## 02｜主世界、探索与冒险流程

### 02.1 世界形态与 HD-2D 视觉方向

玩家在具有斜视立体空间感的 2.5D 主世界自由移动。主世界美术方向明确为**参照《歧路旅人》式 HD-2D 观感**：以像素风格角色为主要人物表现，配合富有空间层次和氛围的场景、光影、景深感与镜头塑造，强调场景美感、旅行氛围和视觉沉浸。

这一决定明确的是**视觉目标**，不自动指定必须使用某一种 2D／3D 混合技术、渲染管线、镜头参数或资产工艺。既有逐帧 2D Sprite 角色动画方向继续有效，实际地图生产流程和性能预算仍需原型验证。

主世界呈现连续的旅行、地区衔接和探索体验；设施、副本及特殊地点可以作为**独立加载的场景**。场景功能按两类组织：

- **旅行／氛围空间：** 世界连续感、环境氛围、地区过渡、远近与旅行体验。
- **高密度内容区域：** 城镇、关键设施和重要地点中的化学互动、NPC、角色事件、特殊敌人、重要线索、奖励和具有回访价值的内容。

世界不以巨大面积本身证明内容量，关键是场景能否承载故事、人物、视觉与发现。

### 02.2 剧情驱动的持续冒险

探索的主要内在驱动力是**故事推进**。玩家通过剧情和人物互动获得阶段目标，在前往目标的过程中体验世界、角色与化学现象。人物对话既可以由玩家主动接近触发，也可以由剧情或角色主动发起，两种形式并存。

持续冒险不是短局式的“打完几战全部重置”。玩家推进具有明确引导的章节和世界进程，可中途保存与继续，并在已经体验过的区域利用新知识、角色、能力或构筑重新理解旧环境。

统一的产品循环为：

```text
剧情提出目标／问题
  → 玩家进入主世界旅行与探索
  → 通过场景、人物、事件与化学现象获得线索和启发
  → 接触敌人或剧情战，进入独立卡牌战斗
  → 通过出牌与化学合成解决战斗问题
  → 胜败、发现、角色与世界状态落账
  → 返回持续世界，剧情继续发展
  → 新知识或角色能力带来回访与新的探索可能
```

### 02.3 探索引导：场景线索为主，必要指引不可缺少

探索优先通过**环境异常、场景构图、镜头视角、光照和动态反馈**自然吸引玩家注意值得前往或调查的地点。人物对话承担补充解释、角色表达与剧情推动的作用。

与此同时，地图和任务不能完全没有指引。对关键主线目标，应保留足够清晰的任务信息、地图标识或辅助提示，避免玩家不知道当前要做什么。

统一原则是：

> **玩家应当知道自己要往哪里推进剧情，但不必事先知道沿途会发现什么。**

具体任务 UI、地图标记强度、镜头引导实现方式尚未定案。

### 02.4 探索内容：沉浸优先，不以大量复杂解谜为主体

探索主要依靠**剧情推进、角色互动、场景美感与发现惊喜**成立，而不是持续要求玩家完成高频复杂机关。化学相关的环境互动应具有存在感，但不应演变成反复打断旅行、观看场景与理解故事节奏的强制谜题链。

允许适量与剧情紧密关联的化学交互；其具体数量、复杂度、是否阻断主线、失败反馈和复用方式仍属待设计内容。支线和隐藏区域可以承载额外惊喜，但足以体现 TCA 差异化的代表性化学卡牌合成体验必须在主线得到保证。

### 02.5 元素角色与大世界互动【方向性共识】

元素角色可以在探索场景中使用与自身元素特征相关的能力，与环境产生可感知互动，包括化学现象、环境状态变化和相关剧情反馈。目标是让玩家感到**世界可互动，化学知识贯穿世界与战斗**。

本版只确认这一方向，不确定任何角色的具体地图技能、操作方式、交互对象清单或角色专属机关；不得据此直接进入 14 名角色的批量技能制作。

### 02.6 探索中的化学线索与自然学习【方向性共识】

探索能够带来新的**配方线索、组合启发与化学知识**，但学习过程应融入游玩体验，不设计成频繁弹窗授课、背公式或不断出现“你学会了某知识”的生硬流程。

“自然学习”不等于取消提示、图鉴、合成反馈或成长信息。玩家仍应理解自己获得了什么线索、哪些内容可查询、哪些内容尚未验证。

探索中获得的知识与正式配方发现保持严格区分：

- **探索知识／线索：** 来自观察、剧情、人物、研究或环境互动，可启发玩家未来的组合选择。
- **正式配方发现：** 只有在战斗规则中成功合成并生成产物后，才写入玩家永久存档。

探索线索如何进入候选列表、是否影响配方开放、何时变为可执行内容及提示程度，仍未决定。

### 02.7 探索角色与敌人遭遇

探索时玩家一次直接控制 **1 名元素角色**，可在探索过程中切换已经解锁的角色。地图中的敌人以可见对象存在；玩家接触敌人后发生战斗转场，进入独立横版 2D 场景。战斗只操作 **1 名元素角色**，不因探索存在切换机制而变成同场换人或多角色共用卡组。

战前是否允许更换角色、特殊剧情是否锁定出战角色、敌人巡逻和避战方式仍属待定接口。

### 02.8 地图、任务与叙事体验

世界具有**明确的剧情指引**、完整主线与清晰角色故事的产品目标。长期叙事方向包括分支剧情、长期伏笔、角色群像以及两个方向截然不同的结局；正式剧情和角色文本制作安排在后续阶段，期望专业文学／编剧人员参与。

玩家可通过主线／角色任务、调查物体、环境化学现象及 NPC 互动认识世界。主世界进度、角色成长、知识线索和战斗临时状态分层存储，确保连续世界体验不改变每场战斗的资源重置规则。

### 02.9 战败与检查点

冒险中的战败处理方向为返回**最近关卡节点或检查点**；这是战斗结束后的世界流程，而非改变 HP 胜负判定。已经按战斗规则成功记录的永久配方发现属于玩家存档，不应被普通地图检查点回退无授权地抹除。

## 03｜角色、长期成长与玩家永久资产

### 03.1 角色身份与数量

首个正式版以 **14 名可玩元素角色**为内容规模目标。角色具有自身元素身份、基础 HP、能量初值／每共同回合回复／基础能量上限、可能的技能强度或被动、专属卡牌与候选池、招牌化合物、成长资料及相应角色叙事。14 名**可玩角色**不等于化学配方系统收录的 18 种元素。

角色以**混合方式解锁**，与剧情、探索、其他长期系统共同形成新的游玩可能；解锁角色属于最重要的永久资产之一。

### 03.2 无显性等级的永久成长

角色具有能够永久影响自身 HP、能力及玩法表现的成长。呈现方式不采用传统的 `Lv.1 / Lv.2 / EXP` 进度条与常规升级弹窗，而是在后台累积隐藏成长指标，并通过**对话选项、休息点、战后事件、探索互动、角色交流**等自然展现成长阶段与发展方向。

角色能力的成长强调能力用途变化、已有卡牌产生新的构筑可能、角色倾向差异及能力分支，而非仅靠每级固定涨数值。即便玩家不看到精确的经验值，也能从台词、态度、状态描述、角色主动互动和实际能力变化中感知成长。

成长过程同时服务角色关系与陪伴感；不要求用显性的好感度数字条表达关系。**隐性成长仅作为角色系统特色**，不套用到其他信息系统：

| 领域 | 信息表达原则 |
|---|---|
| 角色发展 | 隐性成长、自然反馈、对话参与 |
| 卡牌与组牌 | 可检查、可规划 |
| 化学知识和图鉴 | 可查询、可追溯 |
| 地图与任务进度 | 清楚可理解 |
| 奖励与功能资源 | 数量、来源、使用结果明确 |
| 存档和检查点 | 可靠且可预期 |

### 03.3 长期资产顺序

**第一梯队：** 角色解锁、化学知识、卡牌／构筑资源。  
**第二梯队：** 世界权限、功能性资源。

基本循环是：探索世界 → 解锁／认识角色 → 获得知识与构筑可能 → 用新的角色、知识或卡组重新理解旧环境 → 再探索。这一循环不以重复刷素材、无限强化装备或长期数值堆叠为核心。

### 03.4 角色构筑方向

玩家在战斗前按角色身份与基础牌组规则配置两张招牌单质；产品方向支持在满足基础构成、角色候选池与经审核内容边界的前提下，进一步自由调整普通元素牌的种类和数量。构筑变化影响战斗初手可执行配方、手牌循环与长期战术体验。

## 04｜卡牌系统、初始牌组与抽牌循环

### 04.1 卡牌类别和来源

| 对象 | 合成材料资格 | 游戏功能与生命周期 |
|---|---|---|
| **普通元素牌 `ELEMENT`** | **可投入**；1 张对应自身元素 1 计量单位 | 真实材料卡，普通循环牌实例 |
| **招牌单质 `SIGNATURE_SIMPLE_SUBSTANCE`** | **不可投入** | 两个可配置招牌槽的特殊战斗牌；名称为单质并不使其成为 `ELEMENT` |
| **固定招牌化合物** | **不可投入** | 角色固定战斗牌；占实际牌组槽位；起手必有 1 张 |
| **本场合成生成的产物卡** | **不可投入** | 成功合成后直接入手；使用结算后本场移除 |

**卡的类型**与**卡实例的来源**必须分别识别。同一化学式、甚至共享基础卡牌效果的固定招牌化合物与本场生成产物，不因名称相同而共享用后去向。

### 04.2 每角色初始牌组

记其他元素牌总数为 `N`，则有效初始牌组：

```text
自身元素 ELEMENT         4 张（固定）
其他元素 ELEMENT         N 张（至少一种不同于自身的元素）
固定招牌化合物           1 张（固定）
可替换招牌单质           2 张（各占一个招牌位）
-----------------------------------------------
牌组总数                 7 + N 张；N ≥ 1；实际下限 8 张
```

- 自身元素牌的 4 张均为真正 `ELEMENT`，可投入合成。
- 其他元素使用**该角色自己的候选池／牌表**，正式牌表按每一种元素列出有限、明确的张数。没有全角色统一的“每种最多 2／4 张”或其他元素牌合计上限。
- **招牌位恰好 3 张**：1 张不可替换的固定招牌化合物；2 张在战斗外可更换、开战后锁定的招牌单质。两个单质位允许选择同一合法候选；各角色的单质候选池独立。
- 招牌单质池与其他 `ELEMENT` 候选池分开，招牌单质不能满足“至少一种其他元素牌”的组牌要求。
- 早期“牌组至少 5 张”的一般要求由当前构成自动满足；正式有效牌组下限是 **8 张**。

### 04.3 起手五张：三保底加两随机

开局恰好抽出 **5 张真实实例**：

1. **固定化合物 ×1**：直接从该角色初始牌组提取其真实实例，而不是额外生成。
2. **两种不同元素的 `ELEMENT` 各 ×1**：优先采用经正式审核且当前可执行的双元素配方对应组合。
3. **其余随机 ×2**：从扣除上述三张真实实例后的可抽池中抽取，已取走的实例不能重复出现；两张招牌单质并无保底起手资格。

起手双元素被视为“可立即合成”的充要检查包括：正式开放配方恰好需要元素 `e1`、`e2` 两种；两张保底牌各是一张真正的 `ELEMENT`；需求计量 `Q[e1]`、`Q[e2]` 满足：

```text
(Q[e1] - 1) + (Q[e2] - 1) ≤ 35
```

即每种元素投入至少一张真实牌后，初始 35「叠」足以补齐需求。多个可行组合以**角色预设组合优先级**选择，指定组合不可用则随机回退。若该牌组没有任何符合条件的正式双元素配方，仍可正常开战，只随机保底两种不同 `ELEMENT`，不创造材料，不虚称起手一定能合成。

### 04.4 随机性、抽牌与回洗

每场战斗生成独立随机种子。测试可以指定种子，并记录随机调用顺序／随机序列，使起手、剩余随机卡、弃牌堆洗回等可复现；只有同种子但随机调用次序不同，不能视作完整重放。

- 每个完整**共同回合末**，在终局检查通过后玩家常规抽 **2 张**；卡牌效果可以额外抽牌。
- 抽牌堆不足时先取剩余牌，再把弃牌堆洗回补抽；两处不足便只取实际可抽到的张数，包括 **0 张**。
- 手牌可跨己方行动与共同回合保留，且**无数量上限**。
- 手牌、抽牌堆、弃牌堆耗尽均**不是**战斗失败；也不凭空生成替代牌。
- 初始牌、固有招牌和被合成消耗的元素牌进入弃牌并可后续回洗；本场生成的产物牌使用后离场。

## 05｜战斗行动、共同回合与胜负

### 05.1 战斗生命周期

每场 PvE 战斗玩家只控制 **1 名角色**；敌人拥有独立机制。**玩家先手**。定义：

- **行动阶段：** 当前一方拥有操作权并可连续执行多个合法行为的阶段；可主动提前结束，不以花光能量作为结束条件。
- **共同回合：** 玩家行动一次且敌方行动一次组成的完整循环。
- **普通 PvE 行动时间：** **不默认设置固定 60 秒强制操作倒计时。** 玩家可以在己方行动内阅读、思考、尝试配方与调整计量，直到主动结束行动或战斗因其他有效终局结束。

```text
初始化：创建本场实例与随机种子、角色 HP／能量、叠 35、起手 5 张
   ↓
共同回合 1：不额外回能
   ↓
玩家行动（可连续执行合法动作，可主动结束）
   ↓
敌方行动（依据敌方机制连续执行合法动作，可结束）
   ↓
共同回合末：按排序逐项执行周期状态完整效果，每项后检查 HP 终局
   ↓
回合型状态扣减 1 个共同回合持续时间；到期移除
   ↓
尚未终局则玩家常规请求抽 2 张（不足时按牌堆规则处理）
   ↓
进入下一共同回合，按当时有效状态发放能量回复
   ↓
玩家再行动……直至达成终局
```

普通 PvE 取消强制行动倒计时后，**战斗节奏仍需设计和试玩验证**。现有普通战斗约 5～10 分钟的设计目标继续保留，但不由硬性操作秒数自动保证。

### 05.2 终局规则

| 场景 | 结果 |
|---|---|
| 玩家 HP ≤ 0、单体敌方 HP > 0 | 玩家战败 |
| 玩家 HP > 0、单体敌方 HP ≤ 0 | 玩家胜利 |
| 同一次完整结算结束后双方 HP 均 ≤ 0 | **平局** |
| 多单位 Boss 的主体／核心被击败 | 满足玩家胜利条件 |
| 完成规定的 **100 个共同回合**后仍无其他有效终局 | **平局** |
| 玩家主动认输且完成确认 | 玩家战败 |
| 仅有一方或双方没有手牌、抽牌堆、弃牌堆 | 战斗继续，不直接判负 |

**固定 100 共同回合上限**是僵局的唯一自动强制平局触发条件；另有“双方在同一完整结算后同死”这一独立平局规则。不额外设置“连续若干回合未造成伤害自动平局”。战斗中各完整结算单元之后依规则检查 HP，结束后不继续执行后续战斗流程。

### 05.3 出牌与复合效果

合法出牌由权威规则层验证行动权、卡牌实例、固定能量费用、目标合法性和当前接受条件；合法时支付费用、完整处理效果与内部触发、移入相应牌区，最后根据完整结算判断 HP 与终局。

复合卡先按**效果大类的统一优先级**执行，同大类在卡牌内按配置顺序执行；已固定的相对优先级是：

```text
治疗 → Buff → 伤害
```

同张牌的多个独立命中形成多个 `DamageEvent`，按次数响应的防御可逐个事件消耗。反伤和被动引起的触发属于原卡内部的嵌套结算，整条结算链完成后统一检查 HP，系统须阻断无限自触发。

### 05.4 战斗中的临时与长期状态

单场战斗维护即时 HP、能量、手牌／牌区、Buff／Debuff、随机事件、「叠」、回合／行动状态及战斗内卡实例；这些不是连续世界的同一种进度。永久配方发现、角色解锁、成长、世界权限、知识和任务记录则属于跨战斗的玩家存档／世界状态。

特殊限时挑战、敌方 AI 技术超时及未来 PvP 的时间规则均**不能从普通 PvE 自动推导**；它们需要独立设计和批准。

## 06｜暂停、输入与命令一致性

### 06.1 普通 PvE 不采用强制行动倒计时

普通 PvE 的标准玩家行动**不设置固定 60 秒操作预算，也不设置由该预算派生的硬截止**。因此以下旧规则不再适用：思考时间自动消耗倒计时、图鉴／教程查阅继续走表、倒计时归零自动结束行动、以 `60.000… s` 为边界拒绝玩家命令、为普通 PvE 常驻显示 60 秒 HUD 等。

玩家仍可以主动结束当前行动并交出操作权。未来若设计限时挑战、特殊战斗或 PvP，其时间规则必须作为独立玩法重新定义，不能默认复用已取消的普通 PvE 旧规则。

### 06.2 命令接受与原子结算

取消普通 PvE 的强制时间截止，不改变“**规则层必须先正式接受合法命令，再执行真实状态变化**”的基本原则。

- 出牌必须先验证行动权、卡牌实例、固定费用和目标合法性；合法接受后完整结算。
- 合成必须先验证行动权、实例归属、配方开放状态、精确计量与「叠」余额；合法接受后作为一笔原子交易完整提交。
- 未正式提交的合成预览只是 UI／交互状态，取消时真实元素牌回手、「叠」不扣。
- 动画是否播放完、玩家是否加速或跳过表现，不改变已经被规则层接受的动作事实。
- 任何特殊模式若未来重新引入动作截止，必须另外定义其接受时点、拒绝条件和测试边界。

### 06.3 暂停、失焦与规则结算分离

普通 PvE 虽无行动倒计时，暂停系统仍须明确区分**玩家可操作权、规则结算和表现播放**：

- 主动打开暂停菜单时，应暂停新的玩家输入与需要暂停的表现流程；是否暂停某些后台非战斗系统由工程规格另定。
- 失焦、最小化或切入后台时，产品方向仍可自动进入暂停状态；返回后由玩家手动继续的具体 UX 尚待实现确认。
- 若某张**已合法接受**的卡牌或合成正在执行规则结算，权威规则层应保证这笔交易不会因动画暂停、窗口失焦或表现中断而变成半笔状态。
- 玩家回来后只继续未播放完的表现，不重复执行已经完成的扣血、能量、状态、牌区转移、合成或发现写入。
- 非关键战斗动画的加速／跳过只改变表现，不改变伤害、资源、发现、随机结果或其他规则事实。

### 06.4 技术超时与特殊限时机制的边界【未定】

取消普通 PvE 的 60 秒操作倒计时，**不等于取消所有技术超时机制**。敌方 AI 计算、外部服务请求、异步任务或故障保护可能需要工程层超时与降级，但其阈值、触发点、回退方式尚未批准。

同样，限时挑战可以作为未来独立玩法设想，但当前不是已批准制作的标准功能。

## 07｜能量、状态与防御规则

### 07.1 能量储存与费用

普通战斗卡牌支付固定非负整数费用，可为 **0 费**；Buff、Debuff、被动或其他卡牌不改变普通牌的实际固定费用。**合成动作本身额外能量费用为 0**，但产物卡生成后再使用仍须支付其自己的固定费用。

角色的默认基准为：**初始能量 4／每共同回合回复 3／基础能量上限 10**；三个数据由角色分别设定，不要求所有角色相同。未使用的能量可以跨共同回合保存，最多保留到当时有效上限。首个共同回合只获得初始能量，**没有额外回复**。

### 07.2 能量上限与回复的统一公式

同一个状态 ID 遵守同状态覆盖规则，不按重复堆叠重复计数；不同有效状态 ID 的修正可以相加。

```text
Cap_effective   = max(1, Cap_base + sum(有效且不同状态 ID 的上限修正))
Regen_effective = max(1, Regen_base + sum(有效且不同状态 ID 的回复修正))

上限变化后：  Energy_now  = min(Energy_now, Cap_effective)
新共同回合：  Energy_next = min(Energy_now + Regen_effective, Cap_effective)
```

有效上限和有效回复均最低为 **1**。当前能量超出降低后的有效上限时立即舍弃，之后提高上限**不会返还**过去舍弃的能量。共同回合末到期的状态不参与下一共同回合回复。例：默认 `4／3／10` 且不出牌时，第一、二、三共同回合开局分别持有 `4、7、10`；当前有 12 点能量而有效上限从 13 降为 10，则立即变为 10。

### 07.3 Buff／Debuff 的生效、覆盖和持续时间

- **回合型状态施加时立即生效**，并在**施加所在共同回合末**就扣减 1 回合。
- 周期状态在共同回合末先执行本次完整周期效果，再扣剩余持续时间和移除到期状态；周期效果各自完成后进行 HP 终局判断。
- 多个周期状态按**状态优先级 → 实际施加顺序 → 稳定状态 ID**排序。
- 按次数触发的状态对每个**独立伤害事件**分别减少一次，次数归零便移除。
- 同一状态 ID 仅采用**回合型或次数型其中一种**计时机制。
- 相同状态 ID 不叠加强度或时长，保留**最强**；同强且同为回合型则保留剩余共同回合数**更长**者。不同 ID 的能量增减修正可累计。

例如本共同回合才施加的 1 回合保护状态，可能在本共同回合末就到期；不能按“下一整个回合之后才开始倒数”实现。

### 07.4 防御处理顺序

正式伤害系统采用**百分比抗性与乘法区间**的复杂计算方向。进入防御阶段时，固定顺序为：

```text
形成护盾前伤害 → 先由护盾吸收 → 对剩余伤害应用抗性 → 扣除 HP
```

数值型吸收护盾与按伤害事件次数抵挡的防御状态是不同概念；多段伤害按独立 `DamageEvent` 逐次处理相关次数型状态。

## 08｜元素范围、真实化学与配方审核

### 08.1 当前 18 种元素

化学收录仅覆盖周期表第 1、2、3 周期的**主族元素**：

| 周期 | 元素 |
|---|---|
| 第 1 周期 | **H、He** |
| 第 2 周期 | **Li、Be、B、C、N、O、F、Ne** |
| 第 3 周期 | **Na、Mg、Al、Si、P、S、Cl、Ar** |

这 18 种是化学配方审查范围，并非直接承诺 18 名可玩角色，更非保证全部可能组合均有真实产物。

### 08.2 化学真实性与内容开放

1. **真实科学依据是先决条件**：产物、反应物、元素计量和可接受的实际化学条件须接受审核；游戏不凭空发明物质。
2. **反应物限于真实 `ELEMENT` 牌**：当前不实现独立温度／压力操作，不以化合物作二次反应物，不使用独立溶剂牌系统；现实实验条件用于审核资料，但不自动转换成玩家操作变量。
3. 相同元素组合可以对应**多个真实合法产物**；不同真实单质形态亦可分别建立配方记录和产物卡。提交前由玩家选定一种产物。
4. 每次成功合成**只生成 1 张所选产物卡**，属于卡牌玩法抽象，不等于自动执行真实方程式的产物系数配平。
5. 已正式收录的配方具有科学依据、元素计量需求及审核记录；同时经过卡牌内容／平衡审核，才能成为玩家可执行条目。不是所有真实存在的产物都必须制作卡牌。

### 08.3 合法性、审核、开放与发现是不同字段

正式**配方合法性**使用两态：**合法／不可用**；不把早期 `LEGAL / INVALID / NOT_REVIEWED` 三态提案当作正式合法性枚举。科学审核状态、正式游戏开放状态、玩家是否发现及当前能否支付材料，属于不同维度。没有科学审核依据的组合，既不能用于正式提交，也不能计作起手“已保证合法合成”的候选。

科学审核核对真实化学和计量，卡牌内容审核决定是否开放、卡 ID、显示名、固定能量费用、战斗效果和发现表现；二者共同构成玩家可执行配方的入口。

### 08.4 知识获取、探索线索与正式配方发现

**知识获取**可以来自探索、观察、研究、剧情和世界互动。其目标是在不把探索做成课堂或高频复杂解谜的前提下，让玩家自然接触化学现象、反应线索与组合思路，并在后续战斗中形成新的尝试方向。

**正式配方发现**仍有严格战斗规则：只有**成功合成并生成产物**才正式登记到玩家存档。探索中看见、听见、研究到或提前揭晓某种信息，都不能自动写作“已成功发现该配方”。

当前尚未决定探索线索如何进入配方候选列表、是否改变可执行开放状态、提示到什么程度、是否关联奖励。实现时必须把至少以下概念分开：

- 玩家已经接触的知识／线索；
- 配方是否通过科学与内容审核；
- 配方是否对当前玩家正式开放执行；
- 玩家是否曾成功合成并完成正式发现。

## 09｜「叠」资源与合成计量

### 09.1 「叠」的用途和边界

- 每场战斗开始：**35／35**；最大容量固定 **35**，不跨战斗继承。
- **不会在共同回合末自然恢复**；仅特定卡牌、被动或特殊效果能补充，且不能超过 35。
- 每 1 个「叠」能为已经投入至少 **1 张对应真实 `ELEMENT`** 的某元素补足 **1 个配方单位**；不能替代某种元素最初的真实牌。
- 合成花费的「叠」与生成卡自己的能量费是两套资源；合成本身耗能为零。
- 合成区域不限定只能放入两张材料卡，真实投入数量由配方需求、现有手牌与玩家分配决定。

### 09.2 正式计量判定

对任一已经批准且开放的配方 `r`，设其需要的元素集合为 `E(r)`，对每种元素 `e`：

- `Q[e]`：本配方要求的正整数元素单位；
- `H[e]`：本次提交时玩家可合法投入的该元素真实手牌张数；
- `C[e]`：本次实际投入的该元素真实牌张数；
- `S[e]`：本次实际花费的该元素「叠」数；
- `Stack_now`：提交前真实可用「叠」余额。

**全部约束必须同时满足：**

```text
对每一个 e ∈ E(r):
    H[e] ≥ 1
    1 ≤ C[e] ≤ min(H[e], Q[e])
    S[e] = Q[e] - C[e] ≥ 0

对整条配方:
    Σ S[e] ≤ Stack_now
    不投入配方以外的元素
    不投入超出 Q[e] 的额外材料
    反应物只允许 ELEMENT
```

必须由**真实元素牌 +「叠」恰好凑齐每个元素的配方需求**。这套规则同时适用于单质与化合物，不额外强制单质消耗至少两张同元素实牌。缺材料、非法、数量超额或不足都不能形成部分扣款。

### 09.3 计量说明例

以一条仅用于说明数学、**不表示正式卡牌收录**的假设 `H₂O` 配方为例，假定需求 `H = 2, O = 1`：

| 真实材料 | 「叠」支付 | 数学判定 |
|---|---|---|
| H×1 + O×1 | 为 H 补 1 | 符合计量 |
| H×2 + O×1 | 0 | 符合计量 |
| H×2、没有 O | 尝试为 O 补 1 | 不符合：不能创生未投入的 O |
| H×1 + O×1 | 0 | 不符合：H 需求未补足 |
| H×3 + O×1 | 0 | 不符合：投入了过量 H |

## 10｜合成预览、快捷合成与发现存档

### 10.1 手动探索合成

玩家在己方可操作时把真实 `ELEMENT` 牌放进反应**预览区**，系统从已批准合法、已正式开放且满足反应物约束的配方中展示产物候选。未发现者初始显示为“未知产物 ?”，玩家选择候选后，在**正式提交之前**揭晓其身份与计量需求。预览、揭晓、选择、取消均不等于成功发现。

### 10.2 已知配方快捷合成

已成功发现或默认公开的配方可以在快捷列表定位并进入预览。玩家即使材料不齐也可以查看预览，系统清楚列出**已有数量、配方所需与缺口**，但禁止非法确认。

自动推荐的已确认目标顺序为：

1. **先保证整条配方能够完成**，优先补齐不可避免的材料缺口。
2. 在能够完成的合法分配中，**优先用「叠」节省实际投入的真实元素牌数量**，而不是优先节省「叠」。
3. 仍有选择时，剩余可分配的「叠」优先分给**当前手牌张数更少的元素**；同数按配方中稳定的元素顺序。
4. 玩家始终可以在确认前覆盖自动推荐，任何手动比例只要满足精确计量都可提交。

### 10.3 原子合成交易

```text
选牌或选择快捷配方
  → 预览；真实材料临时摆放，未扣牌、未扣叠
  → 筛选合法候选；选择具体产物；未知身份在提交前揭晓
  → 分配实牌与叠；展示所需、拥有、缺口、产物固定费用
  → 点击“确认合成”
  → 权威规则复核行动权、实例归属、配方、计量、叠余额及当前接受条件
     ├ 非法：拒绝，不发生部分扣款；取消预览按原位返还
     └ 合法并正式接受：一笔完整提交
        ├ 真实投入 ELEMENT 进入弃牌堆
        ├ 支付相应叠，合成本身不支付能量
        ├ 手牌直接生成恰好 1 张目标产物牌，并记录“本场合成来源”
        ├ 首次成功时登记配方发现，执行可靠玩家存档要求
        └ 向 UI 发布这笔真实事件的表现结果
```

玩家取消预览、主动离开尚未提交的预览状态或本场因其他规则结束时：未提交材料不得产生扣款。已经被规则层合法接受的合成必须完整执行，不能因动画中断、失焦或表现跳过被拆成半笔交易。刚生成的产物卡在当前行动仍合法且能支付它的固定费用时**可以立刻打出**；也可留在无上限手牌中。

普通 PvE 当前没有固定 60 秒硬截止；若未来特殊模式设有独立限时规则，其超时拒绝语义需在该模式中另行规定。

### 10.4 实例生命周期

| 行为／来源 | 正式去向 |
|---|---|
| 初始普通牌或初始招牌卡打出 | 完整结算后进弃牌堆，之后可洗回 |
| 合成成功消耗的真实 `ELEMENT` | 进弃牌堆，之后可洗回 |
| 本场成功合成所生成的产物卡打出 | 完整结算后**从本场移除**，不进弃牌堆 |
| 名字与生成产物相同的初始固定化合物卡打出 | 依**初始卡来源**进入弃牌堆，正常循环 |

一张真实卡牌实例任何时候只应处于一个真实区域。应以卡实例来源／唯一实例身份识别生命周期，而不以卡名判断。

### 10.5 图鉴、已发现与存档

配方第一次**成功合成并生成产物**，才成为该玩家的“已发现配方”，写入**玩家存档**，供后续战斗和不同角色共享，并进入图鉴／快捷列表。预览揭晓、取消、失败和动画重播不能产生新发现；默认可见的快捷条目亦不等于玩家已发现。

图鉴与合成至少区分以下概念：

| 概念 | 含义 |
|---|---|
| 科学与内容合法 | 已有科学与游戏内容双重审核支持，可正式执行 |
| 当前可执行 | 现时处于允许合成阶段，材料和「叠」足够 |
| 玩家已发现 | 玩家存档记录过成功合成该配方 |
| 默认／快捷可见 | 该配方对玩家公开或已发现，可方便地检索 |
| 图鉴可见 | 已发现的结果能在图鉴查阅，未发现内容按未解锁方式呈现 |

**成功发现需要可靠、原子化、可恢复的存档语义。** 战斗成功合成事实、发现记录、展示反馈必须一致。存档状态按玩家记录，不因转换角色和战斗而消失。

### 10.6 已执行动作的撤销

在**当前己方行动阶段**存在“可撤销部分已执行动作”的规则框架；该能力只适用于明确获准的**动作白名单**。取消未提交预览不属于对已执行动作的撤销。所有已合法提交的交易仍必须首先按完整事务执行，不能把半途扣款称为撤销。

## 11｜敌人、AI、Boss 与可见意图

### 11.1 敌人机制与战术信息

敌人可以有独立的战斗机制，不必复制玩家的手牌、卡组、抽牌过程、35「叠」或发现图鉴。常规敌人依 HP 结算；多单位 Boss 以主体／核心击败作为玩家胜利条件。玩家能够查看敌方 **HP、外部状态及下一次行动的类型／意图提示**，不要求公开 AI 的完整内部推理。

### 11.2 敌方 AI 的权责边界

敌方每次行动先由**权威战斗规则引擎**给出合法动作集合，AI 只在该集合中选择行动；选择结果再由规则层校验并执行。AI 本身**不能直接修改 HP、手牌、能量、Buff、「叠」或任何真实战斗状态**。

AI 可以在自己的行动阶段连续选择合法动作并提前结束。失联、非法输出或推理故障时采用**确定性的合法保底动作**；合法动作集合为空则跳过。敌方难度设计围绕战术质量与合法选项，不将单一“反向选择”作为既定算法。

普通 PvE 已取消统一的每方 60 秒产品级行动时限，因此**AI 不再默认受同一 60 秒硬截止约束**。如果 AI 使用外部模型、异步服务或存在可能阻塞体验的计算过程，必须另行定义技术响应阈值、降级触发点、保底优先级和故障保护；这些属于工程／AI 专项规则，目前尚未定案。

### 11.3 AI 服务接入边界

`jev` 接入被明确**暂缓**：项目不把某种 `jev` 当作现阶段单场战斗必须依赖的已部署服务，也不把某个离线 AI 替代方案视为既成事实。

## 12｜UI、视觉、动画与辅助体验

### 12.1 主世界视觉与探索 HUD

主世界视觉方向采用**参照《歧路旅人》式 HD-2D 的观感目标**：像素风格角色置于具有空间层次、光影氛围和镜头表现力的场景中，强调场景美感与旅行沉浸。该方向不直接指定最终技术管线。

整体 UI 参考《**明日方舟：终末地**》一类的**现代、克制、简洁、层级清晰**的信息设计；参考重点是信息组织与视觉语言，**不是照搬美术资产**。探索 HUD 走**极简沉浸式**方向：必要信息常驻，其余地图／任务／角色／系统信息按需展开。

地图和任务 UI 必须做到“关键主线目标可理解”，同时避免把所有沿途兴趣点提前变成清单。场景构图、光照、镜头和动态反馈承担相当一部分自然引导职责。

### 12.2 战斗 HUD 与信息层级

战斗 UI 对玩家呈现当前角色 HP／能量／「叠」／状态、敌人 HP／意图、手牌、合法目标、合成预览及缺口、快捷配方、图鉴入口、暂停与本次动作反馈等关键信息。

**普通 PvE 不常驻 60 秒倒计时**，也不以时间归零强制结束标准玩家行动。元素种类与卡牌身份用名称、符号或图标共同区分，而不只依赖颜色。

### 12.3 卡牌操作与合成演出

战斗同时支持**拖拽出牌**与**点击选牌＋点击目标**。两者共用同一规则接口，包括：行动权、合法目标、费用与材料检查、预览取消及完整提交语义。非法目标不作为可提交对象；材料不足可预览但不能确认。

合成表现按玩家经历区分：**首次正式发现**强调更华丽的揭示与反馈；**已知配方**强调快捷和高效率。可加速／跳过非关键战斗动画，但只修改表现，不会引起第二次伤害、重复合成、资源扣取、发现或不同的规则结果。

主线流程必须保证至少出现足以代表 TCA 差异化的化学卡牌合成体验；不能把所有高质量合成惊喜都藏在可错过的支线或隐藏区域。

### 12.4 角色动画与战斗反馈

角色主要采用**逐帧 2D Sprite 动画**，不以 Live2D 或 2D 骨骼动画作为现阶段角色的主要制作方法。其他层面仍可配合粒子、Shader、Tween、镜头、光效及 UI 动态反馈。

战斗“爽感”由**出牌响应、角色动作、受击、元素 VFX、镜头、停顿、声音以及节奏**多因素组合形成，不以单一特效种类替代整体体验。首次外部试玩优先验证：出牌是否顺手、动画反馈是否清楚、结果是否可感知、化学合成是否具有发现高潮、普通 PvE 在没有强制倒计时后是否仍保持合理节奏。

### 12.5 可访问性与辅助设置

首个可玩版本优先考虑：**字体大小／UI 缩放、减少闪烁、降低屏幕震动、降低特效强度、非关键动画加速／跳过、色彩辅助、元素图标／符号辅助辨识**。键鼠操作完整，部分手柄支持作为平台目标；演出与玩家可操作权利相分离。

普通 PvE 不再需要围绕“延长标准 60 秒倒计时”设计辅助模式。若未来出现独立限时玩法，其无障碍设置应在对应玩法中单独规定。

### 12.6 教学与自然学习

教学首先确保玩家理解可操作规则，而不是要求玩家记忆化学课本：

1. 普通卡固定费用、HP、玩家先手与主动结束行动；
2. 每种反应元素至少投入一张真实 `ELEMENT` 与「叠」的计量补足；
3. 未知候选揭晓与“正式成功发现”不是同一件事；
4. 合成产物本场生成、使用后移除，而初始元素牌循环回洗；
5. 探索中获得的化学线索是启发，不自动等于图鉴已发现；
6. 普通 PvE 没有强制 60 秒操作倒计时，玩家可以阅读和思考后再确认行动。

探索中的化学学习以**好玩且自然**为目标，优先通过场景、角色、事件和可观察现象提供启发；是否使用明确提示、候选高亮或其他辅助方式仍待设计。

### 12.7 正式音频方向

正式 BGM、声音整体风格与配音内容的制作排在后续阶段；目前以战斗出牌、合成、角色表现和 UI 事件可挂接音效为接口方向，配合首次试玩所需的基础反馈验证。

## 13｜奖励、构筑、存档及跨系统衔接

### 13.1 奖励与解锁

胜利奖励采用**多种奖励组合，并随战斗类别变化**的产品方向。奖励围绕角色解锁、化学知识、卡牌／构筑资源、世界权限及必要功能资源展开。成功发现配方除了图鉴记录，也可关联多种长期回报；同一首次发现事实要与其他奖励系统一致，避免同一一次性事件重复发奖。

### 13.2 玩家存档与世界状态层次

| 状态层 | 主要数据职责 |
|---|---|
| **玩家永久存档** | 已发现配方、角色解锁、永久成长、卡组配置、长期知识、任务记录与永久资产 |
| **世界／探索状态** | 当前位置、地区、检查点、剧情进程、NPC／物件与地图敌人状态 |
| **战前配置** | 当前出战角色、角色有效基础属性、获准牌组及招牌配置 |
| **单场战斗** | HP、卡牌实例和各牌区、随机种子、Buff／Debuff、能量、「叠」、回合和行动命令 |

世界长章节的存档与继续不使本场「叠」跨战斗继承；每次开战仍是 **35／35**，并重新初始化本场卡实例、随机种子与开局抽牌。图鉴配方发现属于永久玩家资产，和地图检查点的临时回退不是同一种状态。

### 13.3 规则、表现和持久化必须一致

- **规则层**是唯一可信战斗事实；显示动画、音效、UI 重放不改写 HP 或卡牌结算。
- **每张牌实例仅处于一个区域**；合成材料进弃牌，产物进手，来源决定使用后去向。
- **所有正式合成是原子交易**，预览取消无扣款，正式接受的动作完整完成。
- **永久发现按玩家存档记录并可靠保存**，跨角色和战斗共享。
- **AI 只选择合法动作**，不直接写入真实数据；故障回退不得绕过权威规则，技术超时机制另定。
- **持续世界体验不等于同一场战斗无限延续**，要明确分隔短期临时资源与长期持久资产。
- **探索知识与正式配方发现分层记录**：玩家在世界中得到启发，不自动等于已经完成战斗合成发现。

## 14｜Demo 与开发推进

### 14.1 Demo 的目的和可玩角色

Demo 不只是一个孤立的单场战斗原型，而要证明 **“剧情 → 探索 → 化学发现 → 卡牌战斗 → 剧情继续”**能够形成完整、可感知、可继续拓展的 TCA。Demo **2 名可玩角色**，这一数量是已明确的体验方向；它不改变正式版 14 名的规划规模。

Demo 需要同时验证两件事：

- 玩家在化学卡牌合成后是否产生“**原来卡牌合成还能这么做！**”的核心体验；
- HD-2D 旅行、角色互动、自然化学线索与横版卡牌战斗是否真正属于同一款游戏，而不是几个并列模块。

一段具有代表性的 Demo 体验链为：

```text
剧情给出明确阶段目标
→ 进入 HD-2D 2.5D 探索区域
→ 移动／调查／切换角色，借助场景线索发现值得关注的异常
→ 通过环境、角色或事件自然获得第一次化学启发
→ 接触地图敌人或主线战斗，转场到横版单角色卡牌战斗
→ 使用 ELEMENT +「叠」+ 科学审核配方进行合成
→ 主线内保证出现一次足以代表 TCA 差异化的核心合成体验
→ 胜败结算并返回探索世界
→ 角色／剧情对结果产生反馈，知识、发现或成长状态落账
→ 进入独立特殊场景，进行进一步探索与战斗
→ 挑战 Boss
→ 展示至少一次可感知的隐性成长反馈
→ 使用新知识重新理解过去的环境
→ 保存／继续游戏，体验持久发现
```

Demo 重点不是堆叠 14 人、完整世界或大量敌人，而是证明核心系统**互相支持且实际好玩**。首次外部试玩以出牌流畅度、动画反馈、合成惊喜、战斗节奏、探索沉浸及完整循环连贯性为优先验证目标。

### 14.2 实施次序与模块分工

开发先搭建**可验证的纯战斗规则原型**：随机、卡牌实例与牌区、能量、状态、HP 终局、合成计量、原子提交和可复核测试；再形成有完整 UI 反馈的单场可玩体验；之后扩展复杂状态／Boss 等边界，并与主世界探索、角色、地图敌人、剧情目标、化学线索、奖励和保存／继续串成端到端 Demo。

普通 PvE 的固定 60 秒行动时限已被取消，因此不再把其倒计时／硬截止作为标准战斗原型的必做产品规则。AI 技术超时、特殊限时玩法和未来 PvP 另开专项。

| 责任域 | 职责边界 |
|---|---|
| 战斗权威状态与行动管理 | 阶段／共同回合、HP、指令校验、终局；普通 PvE 无固定操作倒计时 |
| 卡牌实例与牌区 | 牌类型、费用、来源、手牌／抽牌／弃牌／移除 |
| 能量／状态／伤害 | 资源计算、状态生命周期、独立命中、防御结算 |
| 配方与计量 | 化学合法性、需求 `Q`、实牌及叠检验、合法推荐 |
| 合成提交事务 | 原子材料支付、产物生成、发现事件 |
| AI 选择器与回退 | 只选权威合法动作，不直接修改状态；技术超时／降级另定 |
| 玩家图鉴及存档 | 持久发现、探索知识分层、进度一致性、异常恢复 |
| 主世界探索与任务 | HD-2D 场景、角色移动、剧情目标、场景线索、敌人触发、互动、世界进度 |
| 角色／探索能力接口 | 元素角色与环境互动的方向性能力；具体技能尚未批量定案 |
| UI、表现与战斗日志 | 将权威事件可视化、音画反馈、重放与验证；主线核心合成体验的表现支持 |

### 14.3 不可破坏的系统不变量

1. 手牌、抽牌、弃牌数都为零，也不自动输。
2. 每个初始牌实例有唯一身份；起手保底不凭空复制。
3. 「叠」不能创造某配方中根本没投入真实元素牌的元素种类。
4. 未提交的预览不花卡牌／「叠」；已合法接受的动作不能因动画中止、失焦或表现跳过被拆成半笔交易。
5. 权威规则、AI 决策、动画播放及存档职责互相分离。
6. 未经科学与内容双审核正式开放的配方不能作为玩家可合成条目或起手保证依据。
7. 自动合成**先保证成功、再优先节省元素实牌**，玩家可覆盖为任何合法投入比例。
8. 首次成功合成才是正式发现；探索线索、预览揭晓和重播演出都不是。
9. **普通 PvE 不设置固定 60 秒强制操作倒计时**；任何特殊限时玩法必须独立定义，不能偷偷回用旧规则。
10. 已执行动作撤销受正式白名单限制，不代表可以任意回档。
11. 100 回合强制僵局平局与同一结算中双方同死平局并存。
12. 设计规则、开发实现、自动测试、人工验证、发布验收是不同事实，不能互相代替。
13. TCA 的代表性核心化学合成体验必须在主线流程中得到保证，不能只依赖可错过内容。
14. 探索以剧情驱动、沉浸和发现为主体，不得在未批准的情况下演变成高频复杂化学解谜主循环。

### A.1 战斗数学与事件细节

以下没有得到最终数值或完整过程批准，不能由常识自动补全：

1. 从基础攻击数值到护盾前伤害的加／乘顺序、百分比抗性计算、同属性与不同属性抗性组合、取整位置与算法、最小／最大伤害、负伤害、暴击、穿透。
2. 数值吸收护盾与按命中次数生效的防护状态怎样互动；护盾破裂瞬间如何向抗性传递剩余伤害。
3. 效果**大类完整优先级**：Debuff、护盾、抽牌、直接增加能量、增加「叠」、其他资源变化相对于已经确定的治疗／Buff／伤害顺序怎样排列。
4. 同一卡内同类效果的配置语义；反伤、被动和其他连锁的触发栈、深度限制、循环抑制、死亡后尚未执行队列的清理。
5. 全部周期状态的具体优先级数值；真正同时施加时稳定排序标识；额外周期／非卡牌事件的时序。
6. 基础 HP 和角色资源值容错、能量回复型卡／被动的设计、零费无限循环与操作限制。
7. 第 100 回合中各事件与终局的完整流程，以及多单位 Boss 核心同时归零的优先处理。
8. 敌方是否采用独立抽取流程；特殊状态／事件是否在共同回合主序中插入新节点。

### A.2 暂停、输入、技术超时与特殊限时细节

- 普通 PvE 已明确**不采用固定 60 秒强制操作倒计时**；因此不再需要确定标准模式的 59.999／60.000 秒接受边界、图鉴走表、教程走表或倒计时归零自动结束行动。
- 暂停菜单、失焦、最小化、后台运行时的具体工程行为仍需规格化；但已经被规则层接受的原子动作不能因此半途失效或重复结算。
- 两种出牌输入、快捷合成、预览取消、视觉加速和跳过必须走同一权威规则接口，不能因为手势不同改变合法结果。
- 若敌方 AI 依赖外部／异步服务，需要独立确定技术响应超时、重试与降级；这些阈值不是玩家产品级行动时间。
- 旧决策记录曾猜测 `jev` 可能指 **TypeSafe AI 的 Jev / System One**；这只是未核实线索，不是已批准的供应商、版本、接口或本地／联网部署方案。
- PvP、限时挑战或其他特殊模式属于未来方向；先手、回合时长、暂停、断线、动作截止和辅助设置均没有从普通 PvE 自动推导为批准结果。

### A.3 配方审核、卡牌与内容数据

- 18 种元素的“全范围组合”枚举粒度：单元素、双元素、多元素、不同计量、物态、实验条件、同元素不同同素异形体等究竟覆盖到何处。
- 每条真实产物的文献、反应成立条件、审核记录、元素计量 `Q`、审核状态、可开放许可、卡牌效果、固定能量费用、ID、名称、UI 说明、默认显示优先级。
- 科学审核与战斗平衡审核采用独立记录的具体字段和审批流程；审核状态与正式两态合法性不能混成一个字段。未经科学审核不能被玩家执行。
- 旧草案曾提出 `LEGAL / INVALID / NOT_REVIEWED` 作为一体化三态，已被两态合法性决定覆盖；后续可以讨论独立 `review_status`，但枚举尚未获批。
- 配方候选多个合法产物的排序、未知产物揭晓时的 UX、未发现图鉴条目以问号／空格／完全隐藏的展示方式、默认可见配方范围。

- 复制效果生成的牌如何标记来源和生命周期，复制产物是否造成配方发现、复制卡入牌区和移除区如何运作。

| 探索范围膨胀 | 高 | 2.5D／HD-2D 自由探索＋角色切换＋高内容密度扩大地图／关卡工作量；先完成代表性区域 |

| 自由探索与既有单场战斗脱节 | 高 | 需建设地图、任务、遭遇及场景接口，这属于重大产品范围扩张 |

| 检查点与永久图鉴冲突 | 高 | 世界状态回退不得默默取消已经成功保存的发现；单次奖励需幂等 |
| 永久成长与战斗数值基线 | 高 | 区分角色战前有效属性与战斗即时状态；不改变固定牌费 |

| 先做音画但 P0 仍未定 | 中高 | 可以做占位的体验样机，不把测试值伪装成正式公式／配方 |
| 无倒计时后的战斗节奏失控 | 中高 | D1 取消强制 60 秒但保留 5～10 分钟目标；需用内容、敌人、信息量和试玩控制节奏 |
| 战斗反复打断探索 | 中 | 普通战斗目标 5～10 分钟；根据剧情与旅行节奏控制遭遇密度 |
| 拖拽与点击判定不一 | 中 | 两种输入走同一合法动作与提交验收路径 |
| 收集导向清单化 | 中 | 收集融入知识、角色、地图、构筑，不变成独立刷率目标 |
| 过度解谜破坏沉浸 | 中 | 化学环境互动要有存在感，但不把高频复杂机关作为探索主体 |
| 剧情规模和预算 | 中 | 剧情占比高带来人物、演出、关卡成本；正式内容专业化、阶段化 |
| 正式剧情过早定死 | 中 | 分支和双结局保留方向，暂缓具体章节、人物弧与文案 |
| Demo 范围缺乏验收边界 | 中 | 需要端到端可玩路径及验收指标，不能凭候选数量就宣布完成 |
| 可玩角色与探索操作主体映射 | 中 | 探索切角色、进入战斗选人、任务角色与 NPC 对话要统一 |

### C.6 暂不优先追问的局部问题

当前不宜把讨论集中在“单个动画多少帧、某种元素具体开什么门、某张卡具体如何升级、单个机关的解法、单名角色隐藏指标有多少、单个地图点位、具体剧情章节”等细枝末节。应优先收束：**Demo 端到端规格、探索知识→战斗配方接口、整体成长系统、HD-2D 生产原型，以及仍未关闭的战斗 P0。**

## 附录 F｜规则与体验验收场景矩阵（尚未执行）

**使用原则：** 下表承接 v0.5 的验收索引，并按 D1 删除普通 PvE 固定 60 秒硬截止的旧用例。它仍是**待执行测试的预期**，不是 Godot 测试通过报告。对于仍需正式数学／数据／体验标准的用例，要等获批后才能填入具体数值向量。

| 验收域 | 必须覆盖的典型情景 | 正确结果／前置依赖 |
|---|---|---|
| 角色牌表 | 自身 4、其他元素至少一种、固定化合物 1、可重复单质招牌 2；只含一种 `ELEMENT` 的非法配置 | 有效牌组 ≥8；单质招牌不计元素种类；依正式角色牌表 |
| 起手发牌 | 固定化合物和两张不同 `ELEMENT` 保底；两张随机不重复实例；单质招牌不保底 | 恰好 5；记录随机回退与种子 |
| 保底合法配方 | 仅有三元素配方、需求超出 35 叠、无已审双元素配方 | 不误承诺起手可合成；仍可正常开战 |
| 抽牌洗回 | 抽牌剩 1、弃牌有若干、两区都空 | 先取剩余再洗回；允许 0 张；不因缺卡输；可重放 |
| 能量 | 首回合、4／3／10、满上限、不同状态 ID 正负修正、上限降低 | 首回合不额外回能；上限／回复 ≥1；超额舍弃不返还 |
| 固定费用出牌 | 零费卡、所谓减费 Buff、目标非法、能量不足 | 固定费用不被状态改写；非法命令不生效 |
| 状态时长 | 本回合上一回合型 Buff、剩 1 回合的周期毒、同 ID 不同强度 | 当回合末扣；先周期后减时；最强或同强较久 |

| 快捷合成 | 牌足叠少、牌少叠足、手牌少者优先、玩家覆盖比例 | 先保证可做，再尽量省实牌；玩家合法分配有效 |

| 产物即时使用和去向 | 新产物立刻打出、与初始固有牌同名 | 新生成者用后移除，初始者入弃牌；出牌费固定 |

| Boss／终局 | 单体胜负、双方同死、核心先亡、100 回合、主动认输 | 按结果规则终局；100 回合同刻和多核心须补正式用例 |

### 0.2 本轮发现的三处重要冲突／限制

1. **配方数量不等于 4。** 问卷数量项选择“按自定义补充指定”，候选栏实际列出 **8 条**：H₂O、H₂O₂、CO、CO₂、CH₄、NH₃、NO₂、NO。本文保留全部 8 条，另提议先审核并制作 4 条用于首轮验证，**先做哪 4 条尚待批准**。
2. **“覆盖更多效果”与 3～5 分钟的极小原型存在范围张力。** 用户的选择被完整保留，但建议采用“代表性效果必做、复杂效果按依赖分批验证”的实施法；不得声称用户已经批准砍掉正式规则。
3. **35 叠 + 10 张牌 + 3～5 分钟，可能无法充分验证叠的稀缺性。** 尤其 H、C、N 各只有 1 张，无法在同一次合成中多投入这些元素的真实牌；叠可能始终过剩。本轮不擅自改 35 叠，而是记录验证覆盖不足的风险。

### 0.3 本轮新增的整体设计与冻结原则【用户已确认／本轮整合】

Prototype 0 当前不以“把每一张牌、每一回合和每一个敌人数值提前调到最优”为目标，而以**尽快形成可开发、可测试、可复核的最小系统**为目标。

- **先冻结结构与规则语义，再通过试玩调整平衡数值。** 角色定位、卡牌类别、配方职责、敌人测试职责、伤害／状态语义和数据边界属于开工前必须收敛的内容。
- **数值允许配置化调试。** HP、伤害、护盾、能量费用等具体平衡值在不改变规则语义的前提下，可在 Prototype 0 内部测试中迭代。
- **不替玩家预设唯一正确打法。** 原型需要提供真实可比较的选择，但“玩家具体第几回合打哪张牌”属于试玩观察结果，不作为开发前的硬编码目标。
- **敌人、卡牌与角色都服务于核心实验。** 它们首先是验证“元素牌 + 真实配方 + 叠”是否产生策略与发现欲的实验载体，而非独立追求完整内容量或最终平衡。
- **表现反馈也是实验条件。** 合成、出牌、命中、护盾、首次发现和胜负若只有数字变化，可能把“表现不足”误判为“玩法不足”；Prototype 0 必须达到足以激发继续试玩欲望的最低表现完成度。
- **独立开发以纵向切片推进。** 不把工作拆成大量彼此孤立的小系统，也不先完成一套面向未来的通用框架；优先让战斗、合成、表现和持久化尽早形成完整闭环，再迭代质量。

## 2｜测试角色与 10 张卡组

### 2.1 氧角色战斗定位【用户已确认】

Prototype 0 中的氧 O 定位为**玩家最先接触的入门型合成输出角色**。它的任务不是展示所有复杂机制，而是让玩家迅速理解 TCA 的基本战斗语言，并在很短时间内感受到“直接出牌可以行动，进行合成会得到更高效或更适合当前局面的结果”。

**定位关键词：** 低门槛、偏直伤、快速合成、即时反馈、少量防御／功能分支。

结构性要求：

- 不合成时仍有可理解、可执行的基础行动，避免新玩家因尚未掌握化学系统而完全失去行动能力。
- 合成产物应在效率、用途或战术适配上具有**明显诱因**，否则玩家可能绕开 TCA 的核心玩法。
- 氧的主要输出特色优先由**元素牌 → 合成产物**这条链体现，而不是依赖复杂角色被动。
- 入门角色不等于低上限；进阶空间主要来自材料投入、「叠」、能量、产物选择和时机之间的优化。
- Prototype 0 不要求提前规定玩家逐回合的最优路线；是否出现多样打法由试玩记录验证。
- 该定位用于 Prototype 0 的核心玩法验证，**不自动锁定正式版氧角色的最终平衡、全部技能或成长形态**。

## 3｜八条候选配方与首批审核方案

### 3.1 实际候选清单【用户已提供】

| 候选配方 | 原型计量 Q（以化学式表示） | 每种元素各投入 1 张实牌时，需「叠」 | 本次建议 |
|---|---|---:|---|
| H₂O | H×2、O×1 | 1 | 首批重点审核 |

| CO | C×1、O×1 | 0 | 第二批候选 |
| CO₂ | C×1、O×2 | 1 | 首批重点审核 |
| CH₄ | C×1、H×4 | 3 | 第二批候选 |
| NH₃ | N×1、H×3 | 2 | 第二批候选 |

**注意：** 表中计量是按分子式提取的**测试 Q 候选**，不意味着现实反应已经通过科学审核，也不意味着已批准开放。真实反应路线、适用条件、科学证据和卡牌内容审核必须另立记录。每次成功合成只生成一张产物卡是 v0.6 的卡牌抽象，并不直接表示完整化学方程式配平。

### 3.2 建议首批 4 条【建议待批】

| 配方 | 临时费用 | 临时卡效 | 主要验证功能 |
|---|---:|---|---|
| H₂O | 1 | 获得 6 护盾 | 用少量叠形成防御产物 |
| H₂O₂ | 2 | 造成 8 伤害 | 同一元素集合可得到不同产物和收益 |
| CO₂ | 2 | 造成 6 伤害 | 两张 O 代替 1 叠的投入方案；同名不同来源 |
| NO | 1 | 造成两次各 3 点伤害 | 0 叠合成及独立 `DamageEvent` 多段效果 |

**为什么建议这四条：** 配对元素覆盖 H/O、C/O、N/O，能够比较相同元素集合的不同产物；包含 0、1、2 叠的基础支付差异；同时测试防御、单段与多段攻击。不过这些差异**不足以自动证明 35 叠条件下的长期资源压力**。

**本轮整合后的配方职责原则：** 首批配方首先冻结“测试职责”，不提前追求终局平衡。H₂O 负责代表防御产物，H₂O₂ 负责代表高效率单段直伤，CO₂ 负责代表稳定直伤及同名不同来源生命周期，NO 负责代表低叠成本与独立多段 `DamageEvent`。若后续试玩发现某一配方数值压倒其他路线，应优先调整费用／效果数值，而不是立刻推翻配方系统结构。

### 3.3 每条首批配方必须核实的内容

**H₂O（候选）**

- 核对物质身份、真实反应物及可接受的合成条件。
- 核对由 H、O 元素材料对应到游戏 `Q[H]=2, Q[O]=1` 的抽象口径。
- 验证水的防御效果是**游戏化表现**，不误写成现实科学事实。
- 记录科学依据、审核人／版本、游戏卡效、费用和开放许可。

**H₂O₂（候选）**

- 核对过氧化氢真实合成路线的可行性及催化、选择性、副反应等关键条件。
- 不得因物质真实存在就自动宣称简单直接混合 H、O 在任意条件下可以形成目标产物。
- 核对 `Q[H]=2, Q[O]=2` 的游戏化计量，并给出适用理由。
- 审核其相对 H₂O 的卡效差异、费用及战斗价值。

**CO₂（候选）**

- 核对 C 与 O 生成 CO₂ 的反应依据和适用条件。
- 核对 `Q[C]=1, Q[O]=2`；测试 `C×1+O×1+叠×1` 与 `C×1+O×2+叠×0` 的合法性。
- 检查初始固定 CO₂ 与生成 CO₂ 来源不同所导致的卡实例生命周期不同。
- 持有初始固定招牌 CO₂ **不等于**正式发现配方 CO₂。

**NO（候选）**

- 核对 N/O 生成一氧化氮的真实反应条件，尤其涉及的高温或其他条件。
- 核对 `Q[N]=1, Q[O]=1`，验证各投入一张实牌无需叠。
- 验证两段伤害属于两个独立 `DamageEvent`，并遵守完整结算及护盾／抗性规则。
- 审核低叠成本是否造成卡效性价比失衡。

### 3.4 首批 4 条科学证据初核【外部资料核验；正式签署仍待项目审核人】

本轮只判断“是否存在可核验的现实化学依据，足以继续作为 Prototype 0 候选”，不把游戏 `Q[e]` 误写成完整现实反应方程式，也不把反应条件强行变成玩家操作变量。

| 配方 | 科学证据初核 | Prototype 0 处理建议 |
|---|---|---|
| H₂O | **证据充分。** 氢气与氧气燃烧可生成水；现实过程需要点火／活化并释放大量热 | 保留首批；资料中记录燃烧／点火条件，不描述为任意混合即可生成 |
| H₂O₂ | **证据充分但条件最严格。** 文献明确存在 H₂ 与 O₂ 的催化直接合成路线；同时具有选择性、副反应与安全／反应工程问题 | 保留首批，但标记“条件性证据就绪”；必须注明催化与工艺条件，禁止表达为无条件直接混合 |
| CO₂ | **证据充分。** 碳在氧气中完全燃烧可生成二氧化碳 | 保留首批；记录燃烧／氧供给条件 |
| NO | **证据充分。** N₂ 与 O₂ 在高温条件下可形成 NO，自然闪电也是典型高温来源 | 保留首批；明确高温／放电条件，不表达为常温自发生成 |

**初核结论：** 暂无科学理由要求替换 H₂O、H₂O₂、CO₂、NO 这 4 条首批候选。四条均可进入项目的正式科学／内容签署流程；其中 H₂O₂ 的条件与安全表述应最严格。

**证据记录建议：**

- H₂O：通用化学教材中的氢／氧燃烧成水反应。
- H₂O₂：D. W. Flaherty, *ACS Catalysis* (2018), “Direct Synthesis of H₂O₂ from H₂ and O₂ on Pd Catalysts”, DOI `10.1021/acscatal.7b04107`；以及直接合成 H₂O₂ 的催化／反应工程综述。
- CO₂：通用无机／热化学资料中的 `C + O₂ → CO₂` 完全燃烧反应。
- NO：无机化学资料中的高温 `N₂ + O₂ ⇌ 2NO` 路线。

建议在配方数据中新增／填写：`science_evidence_status = EVIDENCE_READY`、`science_conditions_summary`、`science_source_refs`；只有项目指定审核人签署后，再将 `science_review_status` 升级为正式通过。

### 3.5 第二批候选审核要点【暂不制作】

- **CO：** 需核对相关真实生成路径、氧供给和反应条件，才可作为 0 叠候选。
- **CH₄：** 需核对从所允许的元素材料出发可接受的真实合成依据与条件，不能直接从化学式推导可执行反应。
- **NH₃：** 需核对氮、氢化学合成路线、催化剂／条件与计量口径。
- **NO₂：** 需核对相应生成路径与中间过程，避免把复杂反应误当无条件直接生成。

首批若未获双审核通过，应从后备候选中选择可替代相同实验目的的配方，或调整实验；**不得放宽 v0.6 的科学真实性要求**。

### 3.6 最小配方数据字段【建议待批】

至少分开存储：`recipe_id`、产物身份、`Q[e]`、科学依据、科学审核状态与版本、内容审批状态、正式合法性（合法／不可用）、当前开放状态、生成卡 ID、费用、效果定义、默认可见与已发现状态。**合法性、审核、开放、支付能力、玩家发现不能合并成一个布尔字段。**

## 4｜「叠」策略实验与可验证性

### 4.1 不可修改的规则【继承 v0.6】

- 战斗开始叠为 **35／35**，不跨战斗继承。
- 本原型**无额外叠恢复**；共同回合末不自然恢复。
- 每种反应所需的元素至少投入 **1 张对应真实 `ELEMENT`**。
- 叠只能补足已经投入实牌的该元素计量，不能凭空创造某种材料。
- 合成本身能量费为 0，但生成产物使用时要支付其固定能量费用。
- 已投入的真实 ELEMENT 进入弃牌并能再次回洗；生成产物使用后移除。
- 快捷合成建议分配优先“完成配方 → 花叠省实牌 → 照顾手牌稀缺元素”，玩家可以选择任何合法替代投入方式。

### 4.2 必须观察的三类玩家决策【用户已确认】

| 维度 | 期望观察到的行为 | 主要阻碍 |
|---|---|---|
| A：省牌 vs 省叠 | 玩家有意识选择投入额外真实牌或多消耗叠 | H/C/N 仅各一张，投入替代选择少 |
| B：现在 vs 以后 | 玩家根据敌人意图、能量和手牌等待更合适的合成时机 | 短战斗容易即时合成后直接获胜 |
| C：多次小合成 vs 少次大合成 | 玩家比较合成频率、产物强度和后续资源余量 | 35 叠相对测试配方单次成本过于充裕 |

### 4.3 可执行的测试安排【建议待批】

1. **标准开局测试：** 保持 35 叠、10 张正式测试卡和自然对局，记录每次合成后的剩余叠、可选产物、投入比例和是否改变想法。
2. **相同状态选择测试：** 在内部 QA 通过调试工具构造具有 `O×2` 的合法手牌状态，对照 CO₂ 投入 `O×1+叠×1` 与 `O×2+叠×0`；调试状态不得冒充正常随机开局。
3. **重复对局观察：** 每名内部测试者至少进行数次重复战斗，观察玩家是否只是沿用首次教学配方。
4. **无法触发时如实记录：** 若对局几乎不消耗叠且不出现资源取舍，判定该维度**证据不足**；不得据此直接宣布「叠」机制成功或失败。

**重点风险：** 示例四配方从各元素各一张真实牌开始仅需 0～2 叠，单场 3～5 分钟可能远远不足以耗尽 35 叠。在不修改正式规则的前提下，可以设计额外可复核的模拟中途状态或后续专门的牌组／敌人对照实验，但须明确区别于用户已确认的标准 Prototype 0。

**实验完整性原则：** 标准 Prototype 0 继续保留 35 叠，不为了“让叠看起来有用”而在首轮直接降低初始资源。若标准战斗中几乎没有叠压力，应将其记录为真实实验结果，再以 20／15 叠或低剩余叠的调试状态作为**独立对照实验**；对照结果不得与标准样本混为一谈。

## 6｜规则、交互与工程实施

### 6.1 战斗权威状态【必须符合 v0.6】

建立可独立测试的规则层，维护：角色与敌人 HP、能量、有效状态、手牌、抽牌堆、弃牌堆、移除区、卡实例来源、叠、行动权、共同回合、战斗随机状态及结果。UI、敌人策略和动画均不能直接改写权威状态。

关键规则：

- 玩家先手，可在玩家行动阶段连续执行合法动作并主动结束；**没有固定 60 秒倒计时**。
- 第一共同回合没有额外回能。此后每共同回合按有效上限结算回复；普通基准暂用初始 4、每回合 +3、上限 10。
- 每完整共同回合末按规定时序执行周期状态、有效期扣减和常规抽 2 张（抽不到不凭空补牌）。
- 手牌无数量上限；牌堆耗尽不直接判负。
- 先完整接受并提交合法命令，再更新真实状态；动画跳过／窗口失焦不得重复或部分结算。
- HP 终局、同死平局、主动认输、100 共同回合上限平局遵守 v0.6。

### 6.2 Prototype 0 最小战斗规则语义【本轮已确认】

Prototype 0 不为开工而提前设计正式版全部战斗数学，只冻结**当前原型实际经过的规则链**。正式版复杂抗性、穿透、暴击、反伤和递归被动继续保留扩展空间。

#### 6.2.1 DamageEvent 与防御管线

Prototype 0 的基础战斗值使用整数。每次独立命中生成一个独立 `DamageEvent`：

```text
卡牌／效果基础伤害
→ 本事件固定数值 Buff／Debuff 修正
→ 伤害最低截断为 0
→ 数值护盾吸收
→ ResistanceStage
→ HP 扣减
→ 本事件完成后的终局检查
```

- **数值护盾【用户已确认】：** 获得后持续存在，直到被伤害消耗完或战斗结束；不因行动阶段或共同回合自然清空。
- Prototype 0 同来源或不同来源的数值护盾均采用**直接相加**的最小语义；后续若正式版需要覆盖型／分层型护盾，再独立设计。
- 护盾吸收 `min(当前护盾, 护盾前伤害)`；剩余伤害进入 `ResistanceStage`。
- **抗性：** 规则层保留“护盾后抗性”的固定接口，但 Prototype 0 可玩样本默认不配置实际抗性，因此 `ResistanceStage` 首轮为恒等处理；不在本轮提前设计复杂抗性叠加、上下限或属性矩阵。
- Prototype 0 不实现暴击、穿透、负伤害转治疗等正式版扩展数学。
- 多段攻击逐段生成、逐段结算独立 `DamageEvent`；按次数触发状态也逐段消耗。

#### 6.2.2 状态与复合效果顺序

继续继承 v0.6 已确定的状态语义：回合型状态施加立即生效，并在施加所在共同回合末扣减；周期状态先执行完整周期效果再减持续时间；同状态 ID 保留更强或同强时更久者；按次数状态针对独立 `DamageEvent` 消耗。

Prototype 0 的复合效果大类采用以下**测试优先级【用户已确认】**：

```text
治疗
→ Buff
→ Debuff
→ 数值护盾
→ 资源变化（能量／叠等）
→ 抽牌
→ 伤害
```

同一大类按卡牌数据中的配置顺序执行。该顺序为 Prototype 0 的已批准测试语义；是否直接升级为正式版全局优先级，须在后续正式规则评审中另行决定。

#### 6.2.3 触发链边界

- Prototype 0 可玩样本**不实现反伤和复杂递归被动**。
- 规则层允许预留事件钩子，但未批准的钩子不得改变权威状态。
- 不因未来可能存在反伤／被动而在本轮实现完整触发栈、递归深度、循环抑制和死亡后队列等系统。

#### 6.2.4 第 100 共同回合的 Prototype 0 测试语义

第 100 个共同回合完成敌方行动后：

1. 按既定顺序执行共同回合末周期状态，每个完整周期效果后检查 HP 终局。
2. 若未终局，则执行回合型状态持续时间扣减与到期移除。
3. 若仍未出现其他胜负终局，立即登记 **100 共同回合僵局平局**。
4. 不再执行为了第 101 回合准备的常规抽牌或能量回复。

该语义用于关闭 Prototype 0 的工程边界；多单位 Boss 的复杂同刻终局不纳入本轮。

**冻结原则：规则语义稳定，平衡参数可变。** “先护盾后抗性”“多段独立事件”“护盾不自然清空”属于规则语义；“护盾是 6 还是 7”“敌人 HP 是 30 还是 40”仍属于配置化测试参数。

### 6.3 战斗效果的最小可执行覆盖

用户希望“覆盖更多正式战斗效果类别”。建议分为两层以控制原型范围：

| 效果 / 机制 | 实施状态 |
|---|---|
| 单段伤害、多段伤害 | 首批实现；需独立伤害事件 |
| 治疗、数值护盾、抽牌 | 首批实现 |
| 固定能量费、能量回复 | 首批实现 |
| 叠支付与精确计量 | 首批实现 |
| 最小 Buff／Debuff、状态到期 | 为已选卡效提供最小实现 |
| 周期状态 | 在规则层至少提供可独立验证的测试样例 |
| 抗性 | 保留 `ResistanceStage` 接口；可玩样本首轮不配置实际抗性 |
| 暴击、穿透、复杂乘区 | Prototype 0 不做；不提前设计正式版数学 |
| 反伤和复杂被动触发链 | Prototype 0 可玩样本不做；仅允许无副作用事件钩子 |
| 多目标 Boss / 外部 AI | 不纳入 Prototype 0 玩法样本 |

已有正式边界继续遵守：防御阶段**先护盾吸收，再进入抗性阶段**；多段为独立 `DamageEvent`。Prototype 0 已按 6.2 关闭当前可玩样本所需的最小规则语义，不因此宣称 v0.6 中所有正式版战斗数学缺口已经关闭。

### 6.4 手动合成

1. 从当前手牌选择真实 `ELEMENT` 实例，放入**不扣除真实资源**的预览区。
2. 检索已经科学审核、内容审核并对当前玩家开放的候选产物。
3. 未发现候选初始显示“未知产物”；正式提交前可揭晓选定产物身份和计量要求。
4. 展示每种真实材料已投入数量、Q、可用叠、拟支付叠及产物固定能量费。
5. 可调整材料／叠比例，也可取消预览；取消不得真实扣款。
6. 规则层再次验证行动权、实例归属、配方开放、精确计量、叠余额。
7. 合法时一次性移入弃牌、支付叠、生成**恰好一张**产物入手、触发首次发现；非法时拒绝并保持状态一致。

### 6.5 已知配方快捷合成

- 已成功发现或默认公开的配方可以出现在快捷列表。
- 材料不足仍可查需求与缺口，但不可确认。
- 系统推荐投入：**先确保成功，再优先花叠节省真实元素牌，最后分配给手牌更少元素**；允许玩家人工覆盖为其他合法方案。
- 与手动合成共享权威规则接口和事务提交逻辑；UI 操作方式不得改变结果。

### 6.6 教学、UI 与核心反馈【用户已确认】

- 开场短教学保证**至少一次合法成功合成**，但不自动代替玩家正式提交，更不凭空写入发现。
- 完成后鼓励自由组合，允许查阅已经公开／发现的合法配方。
- Prototype 0 使用**原型级完整 UI**，而不是仅用于工程调试的占位界面。至少清晰显示：HP、能量、「叠」、手牌与牌区、敌方意图、材料预览、候选产物、计量差额、确认／取消、快捷配方、结束行动、暂停／重新开局。
- 调试日志可以存在，但不得占据玩家主体验；正常试玩者应当在不读日志的情况下理解战斗与合成。
- 原型可先以点击／选择实现完整操作路径；若加入拖拽，必须复用同一权威接口。输入形式可以简化，但交互反馈不能简化成“点按钮后数字变化”。

### 6.7 Prototype 0 核心表现完成度【用户已确认】

Prototype 0 的表现目标不是正式量产级资产，而是**足以让玩家愿意继续玩、并能真实感知系统差异**。表现层属于核心玩法验证的一部分。

#### 必须有的反馈

1. **合成反馈（最高优先级）**
   - 元素牌进入合成区后有明确聚合／汇聚反馈；
   - 选定产物时突出化学式与产物身份；
   - 正式提交后有短促但有仪式感的合成演出；
   - 产物卡以明确的“生成”方式进入手牌，而不是瞬间静态替换；
   - 首次发现配方需要额外的“新发现”反馈；
   - 合成、生成、首次发现应有可辨识的音效层次。

2. **出牌与命中反馈**
   - 普通攻击、强力合成产物在力度上必须可感知地区分；
   - 命中应至少具备伤害数字、受击闪烁／位移／轻微停顿或同等冲击反馈；
   - 多段攻击必须让玩家感知到多个独立命中，而不是只显示一个总数字；
   - 关键高伤害产物可以获得更明显的屏幕反馈，但不要求每张牌独立制作复杂演出。

3. **防御与状态反馈**
   - 数值护盾的获得、吸收和破裂需要清晰视觉反馈；
   - O₃ 等 Debuff 应让玩家知道“状态已经施加”和“何时被消耗”；
   - 敌方下一行动意图必须醒目，并在变化时有明确刷新反馈。

4. **战斗收束反馈**
   - 胜利／失败有完整的视觉与音效收束，不以突然停止逻辑代替；
   - 重新开始下一局应足够快，降低反复测试摩擦。

#### 音频最低要求

Prototype 0 至少需要：出牌、命中、护盾、合成、产物生成、首次发现、UI 确认／取消、胜利／失败等基础 SFX。BGM 可使用一条原型级循环或临时授权／自制素材验证氛围，**不要求在 Prototype 0 完成正式配乐体系、角色配音或完整音频品牌设计**。

#### 范围边界

- **做：** 核心动作 VFX、Tween／Shader／粒子、必要镜头反馈、基础 SFX、关键 UI 动效。
- **不做：** 全角色量产级逐帧动画、完整角色立绘体系、全卡独立高级 VFX、正式配乐全套、配音、世界级演出资产。
- **原则：** 表现不允许改变权威规则事实；但规则也不能成为把玩家体验推迟到“最后再做”的理由。

## 7｜持久化与测试证据

虽然本次不做剧情、地图和成长，**配方第一次成功合成才登记为玩家永久发现**仍是正式规则，不可为了省事取消。

### 7.1 最小持久化

- 存储测试玩家的 `discovered_recipe_ids`，按明确配方 ID 记录。
- 成功合成与首次发现一一对应；预览、揭晓、取消、失败、动画重播都不增加发现。
- 重新启动后已发现记录存在，并可以用于快捷列表显示。
- 重复发现事件不得重复发奖或重复记账。
- 需要明确断电／写盘失败／重试／恢复的最小一致性策略，并完成用例验收。

### 7.2 每场测试最低记录项

| 类别 | 必须记录的字段 |
|---|---|
| 运行版本 | 构建号、卡表版本、配方数据版本、测试者 ID |
| 随机性 | 随机种子、随机调用顺序／序列 |
| 战斗结果 | 时长、共同回合数、胜负或平局、剩余 HP |
| 合成行为 | 手动／快捷、查看／取消／确认、目标配方、成功或失败原因 |
| 资源决策 | 投入的真实牌、叠消耗、剩余叠、是否覆盖自动推荐 |
| 策略行为 | 产物是否当回合打出、是否主动等待、是否尝试其他配方 |
| 工程质量 | 权威状态变更日志、异常、事务及存档恢复记录 |

推荐允许录屏和观察者笔记，但不得将动画表现作为权威事件真相。

## 8｜验收标准与 Gate 结果

### 8.1 工程验收【必须通过；不依赖体验评分】

| ID | 条件 |
|---|---|
| F-01 | 初始牌组为 10 张真实实例，实例身份唯一，类型与来源准确 |
| F-02 | 起手恰好 5 张；固定化合物及两种元素保底没有复制实牌 |
| F-03 | 不合法配方、缺对应元素、实牌超量、叠不足均不可提交 |
| F-04 | 预览取消无真实资源扣除；已接受合成具有完整原子性 |
| F-05 | 成功合成恰好生成一张选定产物并正确入手 |
| F-06 | 手动与快捷配方在相同合法状态下执行一致 |
| F-07 | 初始卡正常回洗；本场生成产物打出后移除 |
| F-08 | 伤害／护盾／状态／能量遵守已确定时序，未定数学不冒充正式规则 |
| F-09 | 敌方按合法固定循环行动，意图与行为对应 |
| F-10 | 用种子和随机调用顺序可复现关键牌序及结算 |
| F-11 | 首次配方发现持久化、重启仍在、重复事件不重复写入 |
| F-12 | HP 终局、同死、牌堆耗尽、100 回合与认输边界按 v0.6 验证 |

### 8.2 体验观察【用户已确认：先定性，不设百分比硬门槛】

建议由未参与核心规则设计的内部成员体验，并在首次接触、第二场、第三场中观察：

1. **理解：** 是否理解真实元素材料与叠分别承担什么作用？
2. **自主发现：** 教学完成后会不会主动尝试另一种组合／产物？
3. **抉择：** 是否能说出自己为什么省牌、花叠、等待或改变产物？
4. **战术反馈：** 是否会因敌人下一行动意图调整策略？
5. **重复价值：** 重玩时是否产生新的可执行选择，而非只重复单一最优答案？
6. **节奏：** 3～5 分钟目标能否自然达到，合成的操作时间是否挤占战斗乐趣？

内部样本可用于发现问题和调整原型，但**不足以单独证明外部市场需求和商业可行性**。

### 8.3 Gate 结论类型

- **Proceed／进入下一阶段：** 工程测试通过，并且可重复观察到主动探索配方、资源取舍和不同战术路径。
- **Iterate／迭代：** 工程规则正确，但策略性弱、产物过于同质化、节奏拖沓或 UI 难以理解；先调整并复测。
- **Inconclusive／证据不足：** 由于牌组、35 叠或短战斗未能创造策略机会；不得无证据地判定核心机制成败。
- **Hold／暂停：** 无法可靠结算，科学审核不通过且无合理替代，或经过针对性实验仍不能实现核心体验。

Gate 应记录依据、构建版本、参测者观察以及未解决风险，而不只给“感觉不错”的结论。

## 9｜独立开发推进方式与完成路径

Prototype 0 不再按八个彼此割裂的工作包推进。对独立开发者采用**四个纵向里程碑**；每个里程碑都必须留下一个可以亲自玩、能明显获得正反馈的版本。

### M1｜第一场“像游戏”的战斗

目标：从启动到打出胜负已经成立，并且基础出牌有手感。

一次完成：
- 氧的 Baseline A 角色属性与 10 张测试牌；
- 起手、抽牌、能量、出牌、弃牌／回洗、HP、护盾、胜负；
- `TEST_ENEMY_01` 固定意图循环；
- 最小战斗 UI；
- 出牌、命中、护盾、敌方意图、胜负的基础 VFX／SFX。

**里程碑完成感：** 即使暂时没有合成，也已经是一场能打完、看起来像游戏的短战斗。

### M2｜TCA 的核心瞬间：合成

目标：让“元素牌 → 化学产物 → 打出去”成为 Prototype 0 最有吸引力的瞬间。

一次完成：
- 手动合成预览与原子提交；
- 35「叠」支付；
- 首批 H₂O、H₂O₂、CO₂、NO；
- 产物卡即时入手与使用后移除；
- NO 等多段 `DamageEvent`；
- 合成／产物生成／首次发现的核心演出与音效；
- 已知配方的快捷合成复用同一权威接口。

**里程碑完成感：** 玩家第一次真正体验到“TCA 为什么不是普通卡牌游戏”。

### M3｜完整可重复闭环

目标：Prototype 0 从一次演示变成可以反复玩的原型。

一次完成：
- O₃ 等最小状态／Debuff；
- 共同回合末状态、抽牌、回能；
- 配方发现存档与重启恢复；
- Same Seed／New Seed 或同等快速重开能力；
- 基础战斗日志与关键随机种子记录；
- 失败路径、取消、非法合成、资源不足等核心边界正确。

**里程碑完成感：** 退出再打开仍保留发现；可以马上重开再打一局，真正开始产生重复测试价值。

### M4｜测试就绪版本

目标：不再加系统和内容，只把核心体验打磨到足以做有效内部测试。

集中处理：
- 合成、命中、护盾、首次发现的表现节奏；
- UI 可读性、交互摩擦与重开速度；
- Baseline A 卡牌／敌人数值调参；
- 明显 Bug、软锁、状态错误、存档错误；
- 自动测试只覆盖最容易回归且代价高的核心规则；
- 连续内部试玩并做 Gate 记录。

**里程碑完成感：** 这是一个小、短，但别人拿起来会愿意再打一局的 Prototype 0，而不是开发者演示工具。

### 独立开发工程原则

- **纵向切片优先于横向铺系统。** 战斗、UI、反馈、合成尽早连在一起。
- **不为未知未来预建复杂架构。** 不做通用技能编辑器、复杂事件总线、ECS 或可插拔系统，除非当前实现已经明确需要。
- **只保留已知扩展点。** 例如 `ResistanceStage` 可以留接口，但不实现尚未进入 P0 的复杂抗性。
- **不要为了“以后可能用到”增加今天的开发成本。**
- 但**原子事务、权威状态、存档正确性、可重放随机性**属于当前 Prototype 0 的真实需求，不能以“避免防御性编程”为由省略。
- 每次开发都优先选择能让下一次运行“明显更像游戏”的工作，而不是只增加不可见的底层抽象。

### 9.1 Prototype 0 开发冻结包【本轮整合】

进入核心规则开发前，建议只要求以下内容达到“可实现且无歧义”的冻结状态：

| 类别 | 开工前必须冻结 | 可在内部测试中继续调 |
|---|---|---|
| 核心目标 | H1 理解、H2 策略、H3 重复价值及 Gate 口径 | 观察记录模板细节 |
| 氧角色 | 首个角色、入门型合成输出、偏直伤、快速合成、少量防御／功能分支 | HP、能量数值、单卡具体效率 |
| 卡组 | 10 张真实实例的构成、卡类型、实例来源与生命周期 | 费用、伤害、治疗、护盾、抽牌数值 |
| 配方 | 首批可执行集合、计量 Q、审核／开放状态、产物职责 | 产物费用和效果强度 |
| 「叠」 | 35 初始、无回复、支付规则、与实牌的关系 | 对照实验中的资源量 |
| 敌人 | 固定循环、意图可见、规则层合法行动 | HP、攻击、护盾具体数值 |
| 战斗数学 | 伤害／护盾／抗性／取整／状态／多段／终局的语义顺序 | 各类效果的具体系数 |
| 持久化 | 首次成功发现、幂等、重启恢复语义 | 日志表现和调试工具细节 |
| 核心表现 | 合成／命中／护盾／发现／胜负必须存在玩家可感知反馈 | VFX 强度、镜头幅度、SFX 资产与动画节奏 |

**只有左列未关闭的内容会阻塞 Prototype 0 的可信测试；表现反馈不是最后才补的装饰层。** 右列不应成为无限延迟开工的理由，但所有调整必须版本化并可复现。

### 9.2 独立开发工作量说明【不再沿用旧人日表】

v0.1～v0.3 中的 **24～50 人日**是假设“从零搭建、占位 UI、无正式音画”的团队式粗估。现在 Prototype 0 已明确要求核心 VFX／SFX／UI 动效进入测试样本，而且实际执行者为独立开发者，因此该数字**不再作为可靠排期依据**。

当前不继续细拆工时。先完成 M1 的真实纵向切片，再根据本人在现有 Godot 工程中的实际速度，对 M2～M4 做一次滚动估算。这样比在未检查代码库、未验证资产制作速度前给出精确人日更可信，也更符合独立开发节奏。

判断范围是否失控只看一条：**某项工作如果不能明显提高核心闭环的可玩性、合成辨识度、测试可信度或稳定性，就不进入 Prototype 0。**

## 10｜明确不做与不得偷渡的范围【未批准／不做】

Prototype 0 不制作：

- HD-2D 主世界、地图自由移动、探索角色切换与环境化学机关。
- 完整剧情、角色关系、隐性成长与双结局。
- 14 名可玩角色、18 元素全部组合的内容量产。
- 复杂 Boss、多目标敌人、大地图遭遇和高级／外部 AI 服务。
- 完整战前自由组牌编辑器、正式奖励经济与主世界任务／检查点。
- 全角色量产级逐帧动画、完整角色立绘体系、正式配乐全套、配音、全卡独立高级 VFX；**但核心合成、出牌、命中、护盾、首次发现和胜负的原型级 VFX／SFX 必须制作。**
- PvP、联网、特殊限时模式及服务型运营功能。

**例外：** 玩家配方首次发现的最小持久化不可因为“不做长期成长”而取消；核心 VFX／SFX／UI 动效也不可因为“不做正式美术”而取消，因为它们属于 Prototype 0 的验证条件。

## 12｜阶段结论

**Prototype 0 的产品验证方向与氧角色结构定位已经足够清楚，当前应从“继续讨论局部玩法细节”切换到“关闭开工阻塞项 + 冻结结构 + 工程估算”。尚不适合据此直接批准完整版研发。**

依次执行：

1. 完成首批 4 条配方的项目正式科学／内容签署，并确认开放状态；外部证据初核已表明无需更换当前首批集合。
2. 将当前 10 张测试卡与氧角色属性批准为**首轮实现基线配置**，而非最终平衡。
3. 将敌人 HP／伤害／护盾批准为一套首轮基线配置与可选对照值；结构职责已冻结。
4. Prototype 0 当前可玩样本所需的最小战斗规则语义已按 6.2 收敛；不继续为正式版扩展数学拖延开工。
5. 由独立开发者按 M1→M4 的纵向里程碑直接推进；M1 完成后再做一次真实工作量复估。
6. 核心规则、UI 与核心表现同步进入纵向切片，不再把 VFX／SFX 推迟为“最后润色”。
7. 达到测试就绪版本后内部重复试玩，记录玩家**实际产生了哪些选择和是否愿意继续尝试**；不预设唯一正确回合路线，也不为了证明机制而修改标准实验条件。
8. 进行 Gate 评审：**Proceed / Iterate / Inconclusive / Hold**。

> **决策原则：** 现在要证明的是“化学合成带来了其他卡牌游戏没有的策略和发现欲”，而不是提前把整套 RPG 做出来。

## 13｜版本整合变更摘要

相对 v0.1，本版主要整合 2026-10-25 的 Prototype 0 讨论结果：

- 明确氧 O 为**玩家首个、低门槛、偏直伤、快速进入合成**的 Prototype 0 测试角色。
- 将“角色好不好玩”的讨论提升为“结构职责是否足以验证核心机制”，避免在开发前过度预设玩家逐回合打法。
- 明确**结构／规则语义先冻结，平衡数值后调**；具体 HP、伤害、护盾等优先数据化配置。
- 将首批 4 条配方的职责定义为防御、单段直伤、稳定直伤／生命周期、多段伤害验证，不把当前数字视作最终平衡。
- 将敌人定义为核心玩法的**测试仪器**：固定循环和意图属于结构，HP／伤害／护盾属于可调参数；30 为原基线，40 仅为首轮对照候选。
- 明确标准 Prototype 0 保持 35 叠，不为证明机制而擅自降低；资源压力不足时以独立对照实验补证。
- 新增“开发前必须冻结的规则语义”和“Prototype 0 开发冻结包”，把真正的开工阻塞项与可测试期调参项分开。
- 更新下一轮审批表与阶段结论，使后续工作聚焦于配方审核、规则语义、工程估算和核心实现，而非继续扩大玩法细节。

**v0.3 新增：**
- 正式记录用户确认的 Prototype 0 数值护盾语义：**不自然回合清空，持续至消耗完或战斗结束**。
- 冻结 Prototype 0 复合效果测试优先级：**治疗 → Buff → Debuff → 数值护盾 → 资源变化 → 抽牌 → 伤害**。
- 将复杂抗性、暴击、穿透、反伤与递归被动从 Prototype 0 可玩样本移出，仅保留必要扩展接口。
- 明确第 100 共同回合的 Prototype 0 终局顺序。
- 对 H₂O、H₂O₂、CO₂、NO 完成外部科学证据初核；四条均可继续作为首批候选，正式项目审核人签署仍待完成。

**v0.4 新增：**
- 明确 Prototype 0 是**玩家可感知的可玩原型**，不是只有规则正确性的工程验证器。
- 将核心 VFX／SFX／UI 动效列为验证条件；合成演出是最高表现优先级。
- 修正“不做正式美术”的边界：不做量产级资产，但必须做合成、命中、护盾、首次发现和胜负反馈。
- 将原先八个工作包收敛为 **M1～M4 四个独立开发纵向里程碑**，强调每阶段都有可玩的正反馈。
- 明确“不做防御性编程”的含义：不为未知未来预建复杂架构，但不牺牲当前需要的权威状态、原子事务、存档正确性与可复现性。
- 废止旧 24～50 人日作为当前可靠排期依据；改为 M1 完成后按真实独立开发速度滚动估算。
